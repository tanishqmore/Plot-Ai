# PlotAI — AI-Powered Land Analysis & Building Design Advisor

Final year project: upload a plot image / enter plot dimensions → get land analysis →
choose a building type (rowhouse, bungalow, apartment, villa) → get a suitability
recommendation → get a material + cost estimate → view an auto-generated 3D model.

---

## 1. Realistic Scope (read this first)

Four sub-features are bundled here, and they are **not equally hard**. Be honest about
this in your proposal/defense — examiners respect scoping more than over-promising:

| Feature | Difficulty | Recommended approach |
|---|---|---|
| Plot boundary/shape analysis from image | Medium | Image segmentation (SAM/U-Net) or simpler: user draws/traces boundary + enters dimensions manually as fallback |
| Build-type suitability suggestion | Easy–Medium | Rule engine (setback rules, FSI/FAR, plot shape, road width) + ML classifier trained on synthetic/scraped rules |
| Material & cost estimation | Easy–Medium | Deterministic quantity-takeoff formulas (civil engineering standards) × regional rate DB — NOT a generative model |
| 3D model of final building | **Hard if "AI-generated free-form"**, Easy if parametric | **Parametric generation**: pick house type template → plug in plot dimensions → procedurally build walls/roof/floors in Three.js or via Blender's Python API (`bpy`), export as glTF |

**Recommendation:** Build the parametric 3D generator (it's deterministic, demoable,
and still very impressive). Mention true generative image-to-3D (NeRF / diffusion-based
3D, e.g. TripoSR, Shap-E) as **future work** in your report — trying to make that
production-reliable in a final-year timeline is a common cause of last-month panic.

## 2. Tech Stack (current, 2026)

- **Frontend:** React 19 + TypeScript + Vite + TailwindCSS + shadcn/ui
- **3D Viewer:** Three.js via `@react-three/fiber` + `@react-three/drei`
- **Backend:** Python 3.12 + FastAPI (async) + Pydantic v2
- **Database:** PostgreSQL 16 + **PostGIS** extension (for plot geometry/coordinates) + Redis (caching, job queue)
- **ML (image analysis):** PyTorch 2.x, `segment-anything` (SAM) or a fine-tuned U-Net for plot boundary segmentation; YOLOv8/v9 (Ultralytics) for detecting obstructions (trees, existing structures, roads) in the image
- **ML (build recommendation):** scikit-learn / XGBoost classifier over tabular plot features (area, shape ratio, road-facing width, zoning code)
- **3D generation:** Three.js procedural geometry (fast, browser-native) **or** Blender `bpy` headless script called from backend (more realistic renders, heavier)
- **File/asset storage:** MinIO (S3-compatible) for uploaded images + generated `.glb` models
- **Auth:** JWT (FastAPI + `python-jose`)
- **Task queue:** Celery + Redis (for slow jobs: image segmentation, 3D generation)
- **Containerization:** Docker Compose
- **Docs:** Swagger/OpenAPI auto-generated by FastAPI

## 4. Core Data Flow

1. User uploads plot image **or** manually enters `length × width` + shape (rect/L-shape/irregular) + road-facing side.
2. `image_analysis_service` runs segmentation to estimate boundary polygon + area (falls back to manual entry if confidence is low).
3. `plot_analysis_service` computes: area, aspect ratio, orientation, buildable area after setbacks (per local building bylaws you configure).
4. User selects desired build type (rowhouse / bungalow / apartment / villa) from UI.
5. `recommendation_service` scores each build type against the plot (setback compliance, FAR/FSI limit, minimum plot width per type) and returns a ranked suggestion — even overriding user's pick with a warning if infeasible.
6. `material_calc_service` runs quantity-takeoff formulas (bricks, cement bags, steel, sand, tiles etc. per sq.ft. by construction type) × a rates table (configurable per region) → itemized quotation.
7. `model_generation_service` picks a parametric template matching the build type, plugs in plot dimensions and floor count, generates a `.glb` 3D model.
8. Frontend renders the `.glb` in an interactive Three.js viewer (rotate/zoom/walk-through-lite).

## 6. Suggested Timeline (for a final-year project)

1. **Weeks 1–2:** DB schema, auth, manual plot-entry flow end-to-end (skip ML at first).
2. **Weeks 3–5:** Rule-based recommendation engine + material estimation (fully deterministic, get this rock solid first — it's the most "gradeable" part).
3. **Weeks 6–8:** Parametric 3D generator (start with a simple rectangular bungalow, then extend).
4. **Weeks 9–11:** Image segmentation for plot boundary (this is the riskiest part — timebox it; manual entry is your fallback so the app is always demoable).
5. **Weeks 12–13:** Polish UI, write report, prepare demo dataset.

## 7. What's in this scaffold vs what you still build

This repo gives you: working folder structure, DB schema, FastAPI skeleton with
routes/services stubbed and documented, a React + Three.js starter with a working
parametric box-house generator, Docker Compose for Postgres/Redis/MinIO, and
requirements files. You still need to: train/plug in the segmentation model, tune
the recommendation rules to your local building code, fill in real material rates,
and extend the 3D templates.
